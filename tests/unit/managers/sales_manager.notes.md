## How the tests are built
- **People/workspaces** → fixtures `w1`, `w2` (`make_workspace`), `u1`..`u5` (`make_profile` + local `mk_member` for `workspace_members`), matching the cases file's U1 (active, "Sales Lead"), U2 (active, no position), U3 (suspended), U4 (invited), U5 (W2-only).
- **Reference rows** (A1/A2/A3/AX/AD, F1/F2/FX/FD, I1/I2/IS/IU/IX/ID/IE, DM1/DM2/DMX/DMD, P1, TGC1/TGS1/TGX/TGI) → local `mk_tag`, `mk_tag_assignment`, `mk_account`, `mk_factory`, `mk_item`, `mk_dm`, `mk_product` builders plus lettered fixtures (`a1`, `f1`, `i1`, `dm1`, `p1`, …) built on top of them. ST (`statuses` id 10) → `_ensure_status10`, called from the `w1` fixture so every test gets it for free.
- **Orders/lines/deliveries** → local `so(**overrides)` (defaults per Conventions: W1, A1, F1, ST, `SO-2026-010`, …), `mk_line`/`L`-style helper for order lines (LA/LB/LB2/LS/LT/LU built per case via a shared `cd_setup`/`fsi_setup` helper that returns the 4-5 standard lines), `mk_delivery` for `D(...)` (default `DEL-2026-004`), `mk_delivery_line` for `DL(line, qty)`. SO2/SOX are built with the cases file's fixed numbers (`SO-2026-012` / `SO-2026-900`) everywhere, never the colliding default, per Conventions revision 5. Unnumbered extra deliveries in a Given (e.g. SM-CD-17's three extra deliveries) are given explicit `DEL-2026-001/002/003` in listed order, also per revision 5; SM-CD-17 additionally asserts `len(delivery_lines_for(...)) == 1` for the new delivery line (added this session — the case asks for "exactly 1 new delivery line", which the original test checked only implicitly).
- **Y / today** → `datetime.now().year` / `date.today()` read at the top of each test that needs it, never mocked (spec Overview: nothing mocked).
- **T0/T1 range** → `datetime.utcnow()` read immediately before/after the call; event/approver timestamps asserted with `T0 <= value <= T1`.
- **Expire-before-act** → every test flushes setup then calls `db.expire_all()` before invoking the manager, so message text renders from DB-stored (2-decimal) values.
- **Re-read** → local `reread(db, Model, id)` (expire_all + fresh `get`), plus model-specific helpers: `delivery_lines_for`, `events_for`, `ledger_rows`, `approvers_for`. Every write case re-reads through one of these rather than trusting the in-memory object.
- **NW (nothing written)** → `nw_snapshot(db)` / `assert_nw(db, before)`: row counts across all 8 tables named in Conventions, taken before the call and compared after (error cases snapshot/assert inside the same session right after the exception).
- **BUG-720 lock checks** → `SQLCapture` (a `before_cursor_execute` listener scoped to a `with` block around the action only) plus `assert_lock_before_write` / `assert_locks_before_write`, which scan for a `SELECT … FOR UPDATE` on the named table(s) before the first matching write statement. Matches the pattern used by `test_to_inventory.py` / `test_inventory_movements.py`.
- **DB-error cases** (BUG-726 numbering collisions) → `with db.begin_nested(): ... pytest.raises(IntegrityError)`, so the outer session stays usable for the re-read assertions.
- **Schema cases** (`SalesOrderItemInput`, `SalesDeliveryItemInput`, `SalesDeliveryCreate`) build the pydantic schema directly; no database needed.
- **Mocks:** none — spec Overview lists no externals and Conventions lists no race simulations. The SQL-capture listener is observation, not a mock.
- **Return value convention**: every success-path test asserts the manager's return value per the Conventions table (new row id, `(delivery, order)` tuple, order/delivery object, etc.), even when the case's Then column doesn't repeat it.
