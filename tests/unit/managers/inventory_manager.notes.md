## How the tests are built

- **Workspaces/people/manager** → fixtures `w1`, `w2`, `w3` (`make_workspace`), `u1`, `u2` (`make_profile`), `M` (`InventoryManager()`).
- **Factories/Catalog items** → local builders `mk_factory`/`mk_item`, wrapped as fixtures `f1`, `f2`, `f_in` (inactive), `f_del` (soft-deleted), `fx` (W2), `i1`..`i5`, `ix` (W2), each flushed immediately so ids ascend in creation order per the Conventions.
- **Inventory rows** → builder `mk_inv` plus fixture `inv` (binds `created_by=u2` by default per Conventions), and derived fixtures `T`, `TX`, `TD` for the module's named rows.
- **Ledger / counts / re-read**: `ledger_rows(db, ws, factory, item, type)` (bucket rows, fresh), `ws_counts(db, ws)` ((#inventory, #ledger) in a workspace, fresh — the "nothing changed" check for read-only callables), `reread_inv(db, id)` (`expire_all` + fresh `SELECT`), `inv_rows_for(...)` (rows for a bucket, optionally including soft-deleted, by id — used for "exactly one row" / restore checks), `assert_fields(row, **kw)` for multi-field ledger assertions.
- **MISSING** → `missing_id_for(db, Model)` (max id + 100000).
- **Incoming-summary vocabulary** (`PO`, `TR`) → `mk_status`, `mk_workflow`, `mk_po`/`mk_po_line`, `mk_tr`/`mk_tr_line` plus fixtures `s_open`, `s_done`, `s_tr`, `s_draft`, `wf`. `quantity_ordered`/`quantity_received`/`quantity` are NOT NULL DB columns with no real NULL path, so a cases-file "NULL" line quantity is implemented as `0`, which the manager's own `value or 0` fallback treats identically to NULL (best-practice default, delegated by reviewer; already flagged in the cases file for RS-1 and the SQL-capture convention, extended here the same way).
- **Race simulation RS-1** → fixture `race_rs1`, exactly as the cases file's Conventions specify: `patch.object(inventory_dao, "get_by_factory_item_type", return_value=None)` + `patch.object(inventory_dao, "_get_any_by_factory_item_type", return_value=None, create=True)`.
- **SQL capture (lock cases)** → `SQLCapture` (a `before_cursor_execute` listener scoped to the call) + `locked_read_of_inventory(statements)`, matching "a `SELECT` reading `inventory` with `FOR UPDATE`" (INV-U-30, INV-D-13).
- **Savepoints**: INV-C-15, INV-C-28, INV-C-29 wrap the manager call in `with db.begin_nested():` under `pytest.raises(IntegrityError)`, per the cases file's "Savepoint" convention, so the outer `db` session stays usable for the post-call re-reads.
- **Result comparisons**: `page_ids` (list of `.items` ids, in order), `by_type_map`/`by_type_list` (set vs. ordered comparison of `get_inventory_stats().by_type`, per Conventions: "in order only in INV-S-11"), `summary_tuples`/`order_tuple` (field-by-field incoming-summary comparison).
- **Externals mocked**: none beyond RS-1, matching the spec (timestamps come from the database).
- **No test weakened**: every xfail's "fails today on" assertion is present and is the one that actually fails (confirmed by the run below); the one designed non-strict xfail (INV-S-11, BUG-719) is marked `xfail(strict=False, ...)` exactly as the cases file's Revision/Reviewer notes require.

## Fixing the inherited test file (not a discrepancy)

This cases file had already been implemented in a prior pass; the test file existed with 151 tests (one per case id, 1:1, verified by diffing docstring IDs against the cases file — no duplicates, none missing, none extra). Running it surfaced two **test-setup bugs** (not spec/code discrepancies — both are DB constraint violations in the test's own row construction), which I fixed:

1. **INV-P-17 setup** (`_p17_setup`): the cases file's row list is `H = Hex Bolt (STORAGE)`, `N = Nut`, `HD = Hex Bolt **DAMAGED** soft-deleted`, `HX = W2 Hex Bolt Foreign`. The inherited setup built `HD` as STORAGE (via the `_prow` helper, which defaults to STORAGE), which collides with `H` on the unique constraint `(workspace_id, item_id, inventory_type, factory_id)` — a constraint that applies regardless of `is_deleted` (the cases file's own T/TD convention says exactly this: "never together with it — unique constraint"). Fixed by building `HD` directly as `DAMAGED`, matching the cases file's row definition.
2. **INV-IF-15**: `transfer_number` is a globally unique column (`ix_transfer_orders_transfer_number`, `unique=True`), not scoped per workspace. The 5th transfer order (`tr5`, in W2) reused `"TR-0001"`, already taken by `tr1` (W1). Fixed by giving it `"TR-0005"` (5th order created overall, per the cases file's "orders created in the order listed in Given, so ids/numbers ascend" convention).

Both fixes are mechanical (match the cases file's own row definitions); no assertion, expected value, or marker was touched. Re-run after the fixes: 110 passed / 40 xfailed / 1 xpassed, stable across 3 consecutive runs.
