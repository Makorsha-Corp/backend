# Database and migrations

Schema is managed by **Alembic**. The FastAPI app does not run `create_all` at startup.

## Local development

```bash
docker-compose -f docker/docker-compose.yml up -d
cp .env.example .env
alembic upgrade head
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Verify schema after upgrading:

```bash
python scripts/verify_db.py
```

Reset local data and re-apply migrations:

```bash
docker-compose -f docker/docker-compose.yml down -v
docker-compose -f docker/docker-compose.yml up -d
alembic upgrade head
python scripts/verify_db.py
```

## Railway deployment

Railway runs [`scripts/railway_start.sh`](../scripts/railway_start.sh), which:

1. Runs `alembic upgrade head` (fails the deploy if migrations fail)
2. Starts uvicorn

Set `DATABASE_URL` in Railway to your hosted Postgres instance. Pull changes locally, run migrations, confirm, then push — Railway applies the same migration chain on deploy.

## Adding a new table or column

1. Create or update the SQLAlchemy model in `app/models/`.
2. Import the model in [`app/db/base.py`](../app/db/base.py) so Alembic autogenerate sees it.
3. Export from [`app/models/__init__.py`](../app/models/__init__.py) if the model is part of the public package.
4. Generate a migration:

   ```bash
   alembic revision --autogenerate -m "short description"
   ```

5. Run locally:

   ```bash
   alembic upgrade head
   python scripts/verify_db.py
   ```

6. Commit the migration and deploy to Railway.

## Migration chain notes

- **2026-08-01 squash**: migrations `001`–`064` were replaced by a single frozen
  baseline, **`100_squashed_baseline`** (a sanitized `pg_dump --schema-only` of a
  chain-built database — byte-identical to what Railway has). The old chain was
  not replayable from an empty database because `001` ran
  `Base.metadata.create_all()` from *current* models.
- Databases stamped with the old head are adopted automatically:
  [`scripts/adopt_squashed_baseline.py`](../scripts/adopt_squashed_baseline.py)
  rewrites `064_waitlist_signups` → `100_squashed_baseline` and runs in
  `railway_start.sh` before `alembic upgrade head`.
- New migrations are plain incremental revisions on top of the baseline. The
  old per-migration idempotency helpers (`app/db/migration_helpers.py`) are no
  longer required for new work — fresh installs replay the baseline plus real
  deltas only. CI (`.github/workflows/ci.yml`) applies the full chain to an
  empty Postgres on every push, so a broken chain fails fast.
- Keep **exactly one head** — CI fails on parallel heads; merge them with
  `alembic merge` if two branches added migrations.
- Autogenerate caveat: the ORM models and the real schema have known cosmetic
  drift (models declare redundant `index=True` on many PK columns that the
  schema never created, and the schema has hand-written indexes — e.g. the
  pg_trgm index on `items.name_normalized` — that models don't declare).
  **Always review autogenerated migrations** and delete spurious index
  create/drop operations.
- **`alembic.ini`** `sqlalchemy.url` is a placeholder; runtime URL comes from `DATABASE_URL` in `.env` via `alembic/env.py`.

## Startup seeding

[`app/db/init_db.py`](../app/db/init_db.py) seeds **global** subscription plans only. Workspace-scoped defaults (statuses, departments, tags) are created when a workspace is created.
