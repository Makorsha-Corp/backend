## How the tests are built
- **One test per card, in card order**, with a `# [claude] <ID>` comment and `# Then N` before the checks of Then line N (before the `with pytest.raises` line for a `raises:` line). Two parametrized groups whose setup and checks are identical: IK-07 … IK-14 (one changed request field each, param ids `PTS-IK-07` …) and D-05 … D-09 (one `tran_id` each). D-04 has its own test, because its row is in W0.
- **Standing rows**: fixtures `w0 < w1 < w2`, `u1` ("Karim", `karim@example.com`), `u2` ("Rahim"), `u3` ("Selina"), chained so ids rise in order; autouse `standing`.
- **Patched in every test** (autouse `gw`): `app.managers.payment_transaction_manager.get_sslcommerz_client` → `MagicMock` `gw` (`init_session` → OKS, `validate` → OKV(A26)), and `app.managers.payment_transaction_manager.utcnow` → NOW. Patched only where a card names it: `app.managers.payment_transaction_manager.secrets.token_hex` (I-07); `PaymentTransactionDAO.get_by_workspace_and_idempotency_key` (IK-28, IK-29, IK-43, race simulation). Nothing else is mocked.
- **Race simulation**: the card's `side_effect=[None, <the real method>]` cannot be written literally, because a `side_effect` list returns its items and never calls them. `race_side_effect()` returns a function that answers `None` on the first call and calls the real method (fetched after the Given) on the second. IK-43 uses the literal `[None, None]`.
- **Conventions → helpers**: `mk_t(**but)` (T), `mk_x()` (X = T but `tran_id "e"*26`), `ev(db, t, type, at, **but)`, `held` / `paid` (through `svc.handle_gateway_callback`, as the spec Facts require), `first(...)` → `(A, A_ROW)`, and `commit_point` (`db.commit()`, then `gw.reset_mock()`, which keeps return values and side effects). Snapshots are taken after `commit_point` and before X.
- **Named checks**: `reread` (`expire_all` + `get`), `snap_txn` (every mapped column, the unchanged(R) check), `counts` (all `payment_transactions` and `payment_transaction_events` rows, the "nothing written" check), `x_count`, `events`, `event_rows`, `usable`, `clean`. `committed:` lines run one `db.rollback()` first. `spies` / `failing_commit` / `failing_refresh` follow the Conventions text. `failing_*` are context managers wrapped in `pytest.raises(RuntimeError)`.
- **Statement recorder**: a `before_cursor_execute` listener on the session's connection (`db.get_bind()`), active during the When only. "Selects from payment_transactions" means it starts with `SELECT` and contains `FROM payment_transactions`. That excludes `payment_transaction_events`.
- **`_to_response`** is called as the module function `app.services.payment_transaction_service._to_response` (cases rev 2a).
- **Fingerprint** (Conventions, cases rev 2b): `fp(obj)` = SHA-256 of `json.dumps(obj, sort_keys=True, separators=(",", ":"))`; `fpo(u1)` = FPO, `fpx(u1)` = FPX (IK-01, IK-02, IK-44). IK-36 asserts the spec example's literal hash with profile id 7 (`make_profile(db, id=7)`); IK-45 uses `fp({**FPO, "amount": "500.5", "cus_name": "Ali"})`.

## Notes for maintainers
- **When BUG-3023 lands** (45 IK cards, all strict): the service needs the keyword `idempotency_key`, the model needs `idempotency_key` / `idempotency_fingerprint`, and the migration needs the partial unique index with the exact `indexdef` of IK-25. The fingerprint uses sorted keys (spec G8). The race cards patch `PaymentTransactionDAO.get_by_workspace_and_idempotency_key` with `autospec=True`, so the method must exist on the class with the keyword signature `(db, *, workspace_id, idempotency_key)`.
- **BUG-019** (I-03 … I-05; IK-02 and IK-04 need it too) needs the `failed_reason` column. **BUG-3022** (TR-04, RR-11, D-17, L-13) needs `failed_reason` and `outcome_verified` on `PaymentTransactionInDB`. RR-11 also needs BUG-026 (`outcome_verified` True after a resolve). D-17 and L-13 expect `outcome_verified is False` on a row inserted without it, so the column needs default `false`.
- **BUG-028** (TW-03) expects the event type to be the source (`redirect_cancel`). **BUG-023** (GC-13) expects a `validation_rejected` event with GC-12's unchanged description text.
- When a bug is fixed, its strict xfail tests XPASS and fail: remove the marker. D-14 and L-11 are non-strict and can XPASS at any time; remove their markers with BUG-1190 / BUG-2402.
- I-09 and IK-42 rely on workspace id 999999999 not existing (FK error 23503). The tests use fixed `tran_id`s (`"a"*26`, `"1"*26`, …), and `tran_id` is unique across the table. A concurrent uncommitted run that uses the same values only makes the insert wait, never fail.
- `unchanged(R)` compares every mapped column, so it picks up new columns automatically.
