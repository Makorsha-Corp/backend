# Pulling the 2026-08-01 changes — what you need to do

This release swapped several dependencies and **squashed the migration chain**.
Pulling without the steps below will fail to start.

## 1. Reinstall Python dependencies

```bash
pip install -r requirements.txt
pip uninstall -y python-jose passlib
```

`python-jose` was replaced by `PyJWT` (it was unmaintained and had two CVEs),
and `passlib` was dropped — the code always called `bcrypt` directly. If you
skip this you get `ModuleNotFoundError: No module named 'jwt'` on startup.

Other notable bumps: FastAPI 0.109 → 0.141, Pydantic 2.5 → 2.13,
SQLAlchemy 2.0.25 → 2.0.51, pytest 7 → 9.

Existing password hashes and JWTs stay valid — nobody gets logged out.

## 2. Update your database

Migrations `001`–`064` were replaced by a single frozen baseline,
`100_squashed_baseline`. The old chain could not be replayed from an empty
database (`001` ran `Base.metadata.create_all()`, so `031` collided with tables
that already existed).

**You do not need to recreate your database.** Run:

```bash
python -m scripts.adopt_squashed_baseline
alembic upgrade head
```

The first command rewrites your stamp (e.g.
`064_merge_sales_delivery_and_work_order_item_soft_delete`) to the new
baseline; the second applies `101_waitlist_signups`, the one table your
database is missing. Both are idempotent — safe to re-run.

If the adopt script says *"unexpected revision(s)"*, your database is at a
revision it doesn't recognize. Bring it to a pre-squash head with the old
migrations first (`git stash` the new ones), or recreate it from scratch —
`alembic upgrade head` on an empty database builds everything.

`scripts/railway_start.sh` runs both commands automatically, so deploys need
no manual step.

## 3. `.env` (optional)

New keys, all with safe defaults — only set them if you're working on the
landing waitlist:

```
TURNSTILE_SECRET_KEY=
WAITLIST_ADMIN_EMAILS=you@example.com   # optional legacy; platform admins use is_platform_admin
WAITLIST_IP_HASH_SALT=
```

Platform admin bootstrap (Support + Waitlist in ERP): see **[`docs/PLATFORM_ADMIN.md`](./PLATFORM_ADMIN.md)** — production Railway steps, operator guide, and security for Makorsha staff.

`BACKEND_CORS_ORIGINS` gained `http://localhost:4173` (landing preview).

## 4. Verify

```bash
python -m pytest -q          # 113 passed
alembic heads                # exactly one: 101_waitlist_signups
uvicorn app.main:app --reload --port 8000
```

## Writing migrations from now on

- Normal incremental revisions on top of the baseline — the old
  per-migration idempotency helpers are no longer needed.
- **Keep exactly one head.** CI fails on parallel heads.
- **Review autogenerated migrations.** The ORM models and the real schema have
  known cosmetic drift (models declare redundant `index=True` on PK columns;
  the schema has hand-written indexes the models don't declare, e.g. the
  pg_trgm index on `items.name_normalized`). Autogenerate will propose
  spurious index create/drop operations — delete them.
- Keep revision IDs **under 32 characters**: `alembic_version.version_num` is
  `varchar(32)` on freshly created databases.
