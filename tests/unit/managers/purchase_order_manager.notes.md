## How the tests are built
- **Standing rows** → autouse fixture `s` (a `SimpleNamespace`): W0/W1/W2, U1…U5 with their names, the five memberships, per workspace (suffix `0`, `1`, `9`) `SDk/SPk/SRk/SCk`, `WFk`, `Fk`, `Mk`, `Ak`, `Ik`, then W1's A3, I2, I3, PJ1, C1, in the Conventions order, each flushed. `s.TAG` per test; `s.WS` maps the suffix to the workspace.
- **Given rows** → `mk_po(db, s, n, k="1", **cols)` ("po of W0 / W9" with `k="0" / "9"`), and the shorthands as dicts merged into `cols`: `stage(X)`, `confirmed(s)`, `locked_by(s, V)`, `complete_by(s, V)`, `voided(s)` (UP-47 "complete by V, then voided" merges `{**complete_by, **voided}`, so `invoice_id` ends `None`). `mk_line(db, O, k, I, **cols)`, `mk_invl`, `mk_inv(db, s, status, payment, k="1")`, `mk_appr` + `APPROVED`, `mk_ret` + `ret_completed(s)` / `RET_CANCELLED`, `mk_rev`, `mk_evt`, `deleted_factory(s)`, `deleted_machine(s)`, `mk_wx`, `stx`, `mk_pox` (the OX row of SS-06 / SS-09), `mem(...)` (in-memory line, never added).
- **Calls** → thin wrappers that only fill the card's fixed arguments: `CR` (create), `UPD` (update), `AI` (add_item), `UI` (update_item), `RI` (remove_item), `SY` + `SYNC` + `SU` (sync_items), `AA`, `RM_`, `SA`, `FDI`, `DEL` (Conventions "DEL(id)": `user_id=U2.id` only when `inspect.signature` shows the parameter).
- **Named checks** → `reread`, `snap` (every column, for "unchanged(X)"; taken after the last Given line), `gone` (takes the id from the identity key, so a deleted row is not reloaded), `EV`, `types`, `LINES`, `counts` (the 8 tables of "nothing written"), `assert_session_clean`, `status_names` / `status_count` / `status_id`, `purchase_workflows`, `approver_count` / `approvers_of`, `line_count`, `po_count`, `audit_count`, `order_part`.
- **Statement recorder** → `Recorder` on the connection's `before_cursor_execute`, switched on only around the When (`with recording(db) as rec:`); the Given ends with `db.expunge_all()` and keeps plain ids. `rec.locks_first()` implements "locks O first" (a SELECT whose FROM names `purchase_orders` with `FOR UPDATE`, no `SKIP LOCKED` / `NOWAIT`, sent before the first INSERT / UPDATE / DELETE); `rec.sel(table)` the SELECTs whose FROM names a table.
- **Commit spy** → `commit_spy(db, call)`: `patch.object(db, "commit", wraps=db.commit)`, `sp = db.begin_nested()` right before the call, `sp.rollback()` after; returns `cm.call_count`.
- **clock** → `clock()` patches `app.managers.purchase_order_manager.utcnow` (SA-01, SA-10 only). WF-05 / WF-06 patch `app.managers.purchase_order_manager.ensure_po_workflow_record` as their cards say. Nothing else is mocked.
- WE-02 / WF-06 hide every `purchase` workflow with the card's in-test `UPDATE order_workflows ...` (rolled back with the test). It row-locks every purchase workflow in the database for the length of that test, so a parallel test file creating purchase orders may wait a moment; it never deadlocked here.
- Tests that use neither `db` nor `s` (pure helpers, schema cards) list no fixtures; the autouse `s` still builds the standing rows, as the Conventions require.
