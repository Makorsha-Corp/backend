## How the tests are built
Built in **local-coder mode**. The scaffold, four exemplar tests and three more tests (ACC-U-16, ACC-S-02, ACC-UN-12) are hand-written; the other 182 were written by the local model (marked `# [local-coder] <ID>`), one card each, from `account_manager.helpers.md` (10,442 characters after the fix round; limit raised to 10,500 for this module), which is its only view of the test file. Keep that sheet and the scaffold in step: a helper renamed in one must be renamed in the other.

- **Conventions → constants:** `MISSING`, `MISSING2`, `T0`, `NOW`, `FILLED` (dict of the 13 optional fields), `OPTIONAL_FIELDS` (the 13 names, in FILLED order), `OPEN_INVOICES` (the error text, em dash written as `—`; tests compare against the constant and never type the dash), `INVOICE_STATES` (state name → `invoice_status`, `paid_amount`, `payment_status`), `SNAP(**replaced)` (the 17-key audit snapshot; an unknown key raises `KeyError`, so a typo cannot pass silently).
- **Conventions → fixtures:** `w1`, `w2` (`make_workspace`), `u1`, `u2` (`make_profile`), `M` (`AccountManager()`, no constructor arguments).
- **Given rows → builder fixtures** (factory fixtures, so they know W1 and U1 without extra arguments; each inserts one row directly, flushes and returns it, so ids rise in call order):
  - `mk_account(deleted=False, **columns)` — default account; `deleted=True` sets `is_deleted True`, `is_active False`, `deleted_at T0`, `deleted_by U1.id`; `**FILLED` gives the filled account; W2 rows pass `workspace_id=w2.id`.
  - `mk_tag(name, tag_code, **columns)` — default tag (`is_system_tag False`). Revision 2 of the cases writes `tag_code` everywhere; the second parameter was renamed from `code` to match, positional callers are unaffected.
  - `mk_link(account, tag, **columns)` — "A has T": the account's workspace, `assigned_by U1.id`, `assigned_at T0`; does not touch `usage_count`.
  - `mk_invoice(account, state, **columns)` — "invoice of A": an `AccountInvoice` row in the account's workspace, `invoice_type "payable"`, `invoice_amount 1000.00`, `invoice_date 2026-01-15`, `allow_payments True`, plus the three columns of the named state (`draft` / `unpaid` / `partial` / `paid` / `voided`). Inserted through the model only.
- **Named checks → reading helpers** (module-level functions; they only read, hold no expected value and catch nothing):
  - re-read → `reread(db, row)`: `expire_all()`, then `SELECT` by id; works for any model (invoices included) and returns `None` for a deleted row.
  - unchanged(X) → `snap(db, row)` before and after: a Core `SELECT` of every column of the row (no ORM state involved); `None` if the row is gone, so a deleted-and-recreated assignment compares unequal.
  - Invoice rows: `snap` / `reread` / `count_rows(db, AccountInvoice)` are generic and need nothing special; `written(db)` deliberately does not count invoices (the convention lists three tables), so invoice cards assert `count_rows(db, AccountInvoice)` explicitly.
  - nothing written → `written(db)` before and after: row counts of `accounts`, `account_tag_assignments`, `financial_audit_logs` (all workspaces) and `usage_count` of every tag row. The literal numbers a card lists are asserted separately with `count_rows(db, Model, **equals)` and `reread(db, tag).usage_count`.
  - tags(A) → `tags(db, account)`; assignment rows → `links(db, account)` (ordered by tag id) and `link_row(db, account, tag)`.
  - audit(A) → `audit(db, account)`: fresh `FinancialAuditLog` rows with `entity_type "account"` and that `entity_id`, ordered by id. "Standard audit fields" are written out as five asserts in each test.
  - All helpers take the row object, not its id, and read the primary key from the identity (`sqlalchemy.inspect(row).identity`), so they also work on an expired or deleted row.
- **House format `# Then N`:** every test has one `# Then N` comment per numbered Then line of its card, each number once and in order, directly before that line's assertions (before `with pytest.raises(...)` for a `raises:` line; the text check of the error follows the `with` block inside the same Then). For a card whose call itself fails today with the designed `TypeError`, the call stands before `# Then 1`. Checked by script for all 189 tests with the tool's own `then_count` / `then_marks` (numbers equal 1..K, an assertion in every block, no other Given/When/Then comments), and for the 89 xfail tests against the `--runxfail --tb=short` output (the failing line lies in the Then block the card names).
- **Mocks:** autouse fixture `clock` patches `app.managers.account_manager.utcnow` and `app.utils.audit_logger.utcnow` → `NOW` for every test (the spec's Externals). Nothing else is mocked; there are no race simulations. `assigned_at` / tag `created_at` defaults are bound in the models and are not patched (cards only assert `is not None` there).
- **Row counts** are global ("`accounts` has exactly 1 row"): the test database tables are empty and each test is rolled back, so the Given rows are the only rows.
- **Schema-target cards** build `AccountCreate` / `AccountUpdate` only; raising ones sit inside `pytest.raises(ValidationError)`.
- **Database-target cards** (ACC-C-26, ACC-C-35, ACC-A-14; ACC-C-34 is the non-raising variant: plain builder call, then `row.id is not None`): the builder call (which flushes) runs inside `with db.begin_nested():` under `pytest.raises(IntegrityError)`; the savepoint rollback keeps the session usable for the re-read.
- **xfail cards that call a parameter that does not exist yet** (`ip_address`, `user_agent`, `include_deleted`, `include_inactive`, `user_id` on `unassign_tag`) are written exactly as the card shows; the `TypeError` is the designed failure.
- **Exemplars** (hand-written, also shown in the helper sheet; the sheet omits the xfail decorator of ACC-C-17 because the tool forbids markers in generated tests):
  - ACC-U-01 — error with exact text + nothing written + unchanged.
  - ACC-U-28 — happy path with tags, assignment rows and usage counts re-read.
  - ACC-C-17 — xfail BUG-872; `SNAP`, `**FILLED`, audit `changes`. With `--runxfail` it fails on Then 3 (`changes["after"]` has 6 keys), as the card names.
  - ACC-A-14 — `IntegrityError` on flush inside `db.begin_nested()`.

## Notes for maintainers
- xfail reasons of generated tests are `BUG-NNN: <title>` with the title column of `docs/testing/bugs.md` (cut at 90 characters), e.g. `BUG-872: Account audit rows omit bank details and many other fields` — the same text as the hand-written exemplar's constant `BUG_872`. For a precedent bug that was first logged for another module the title is that module's, so the text reads oddly here although the ID is right: `BUG-629: Moving a draft invoice to another account…` (here: inactive tag accepted) (the former `BUG-719` citation for the tag order was a wrong ID, not just odd text: corrected to BUG-1486 in cases revision 3), `BUG-637: Whitespace-only invoice-number search…` (here: name text not trimmed), `BUG-440: Non-members can enumerate which workspace ids exist` (here: foreign-workspace message). Match on the BUG ID, not on the text.
- `local_coder.py --dry-run` prints the prompt to the console; on a cp1252 Windows console it fails on characters outside cp1252, so the helper sheet uses `->` instead of an arrow character. Keep it that way or set `PYTHONIOENCODING=utf-8`.
- ACC-UN-14 (xfail BUG-873) expects `TypeError` from a call without `user_id`; when BUG-873 is fixed the `unassign_tag` pass cards gain `user_id=U2.id` through a cases revision.
- When a test is edited, keep its `# Then N` comments in step with the card (see "How the tests are built"); `local_coder.py` rejects a generated test without them.
- `--runxfail -rf` must show exactly 92 failures (89 before cases revision 3). Eight of them fail with `TypeError` on the call line by design (ACC-C-19, U-42, G-05, G-06, S-02, D-12, UN-12, UN-13: a parameter that does not exist yet); ACC-UN-14 is the reverse (`DID NOT RAISE TypeError`).
- Before a new local-coder run on this file, check for fixtures used but not requested and for snapshots taken after the call (both happened here, and both keep a test green or "xfailed" for the wrong reason).
- Nested `with pytest.raises(IntegrityError): with db.begin_nested():` is the Conventions' form; ruff SIM117 flags it — leave it.
